## 1. 预备知识

### 1.1 五个基本概念

| RL 里的词 | 在语言模型里是什么 | 例子 |
| --- | --- | --- |
| 状态 $s_t$ | 已生成的内容（问题 + 前面的 token） | `"1+1=? <think> 因为"` |
| 动作 $a_t$ | 下一个 token | `"1"` |
| 策略 $\pi_\theta$ | 语言模型本身 | Qwen、LLaMA |
| 轨迹 $\tau$ / 回答 $y$ | 一整段生成的文本 | `"1+1=2 <think>..."` |
| 奖励 $r$ | 对整段回答的评分 | 答对给 1，答错给 0 |

这里有个**非常关键**的细节：

> **奖励通常只给整段回答打一个分，而不是每个 token 一个分。**

比如做数学题，最后用规则检查答案对不对，只能得到"这道题答对了（1 分）"或"答错了（0 分）"。中间那 500 个 token 里哪个写得好、哪个写得差，奖励信号并没有直接告诉我们。

但策略梯度更新是**逐 token** 进行的（每个 token 都要算梯度），所以算法必须想办法把这个"整段一个分"的奖励，分摊或广播到每个 token 上。这就是 PPO 需要价值模型、GRPO 需要组内比较、GSPO 需要序列级比率的原因。

### 1.2 符号总表

| 符号 | 含义 |
| --- | --- |
| $x$ / $y$ | 输入的问题 / 生成的一整段回答 |
| $y_t$、$y_{<t}$ | 回答的第 $t$ 个 token、它之前的所有 token |
| $\lvert y\rvert$ | 回答的 token 数量（长度） |
| $\pi_\theta$ | 当前正在训练的模型（策略），$\theta$ 是它的参数 |
| $\pi_{\theta_{\text{old}}}$ / $\pi_{\text{ref}}$ | 生成这批数据时的旧模型 / 全程冻结的参考模型（通常是 SFT 后的初始模型） |
| $G$ / $o_i$ | 同一道题采样多少条回答（组大小）/ 第 $i$ 条回答 |
| $\hat A$ | 优势（advantage），表示"比平均水平好多少" |
| $V(s)$ | 价值函数，预测从状态 $s$ 出发能拿多少分 |
| $\epsilon$ / $\beta$ | 裁剪范围（控制单次更新幅度）/ KL 惩罚系数（控制偏离参考模型的程度） |
| $D_{KL}$ | KL 散度，衡量两个概率分布差多远 |

### 1.3 策略梯度

训练模型做数学题时，我们希望"答对的概率越来越高"，即想最大化期望回报：

$$
J(\theta)=\mathbb{E}_{y\sim\pi_\theta}\big[R(y)\big]
$$

- $J(\theta)$：目标函数，越大越好。
- $R(y)$：回答 $y$ 的奖励分数。
- $y\sim\pi_\theta$：指回答是**由模型采样出来的**。

这个优化目标可以这样去看：$R(y)$ 越大说明这条回答越好，我们希望参数朝着 $R(y)$ 变大的方向更新。想用梯度上升优化它，就要算 $\nabla_\theta J(\theta)$。

最自然的想法是：**把结果奖励分数直接当 loss，反向传播回去**。但这么做梯度是断的，根本传不回来。因为反向传播靠的是**链式法则**：想让梯度从最右边的 $R(y)$ 传回最左边的 $\theta$：

$$
\frac{\partial R}{\partial \theta}=\frac{\partial R}{\partial y}\times\frac{\partial y}{\partial \theta}
$$

但这条链有两处走不通：采样出来的 token 是离散的，奖励又常常来自一个不可微的外部程序。

**断点一：$\dfrac{\partial R}{\partial y}$ 拿不到——奖励通常不可微。**

奖励由外部程序算出来，没法求导。比如：

- **规则判题**：比较答案字符串相不相等，相等给 1、否则给 0。
- **游戏规则**：赢了 $+1$，输了 $-1$。
- **人类反馈**：人给两个回答排个序。

这些都不是关于 $y$ 的光滑函数。尤其是离散的 $+1/-1$，**导数根本不存在**。


**断点二：$\dfrac{\partial y}{\partial \theta}$ 采样不可导。**

模型先输出一个概率分布，比如下一个 token 是 A/B/C 的概率为 `[0.6, 0.3, 0.1]`，然后**按这个概率抽一个**，这次抽到了 A。这个 A 在代码里就是一个整数编号。

现在设想我们把参数 $\theta$ 微调一下，让 A 的概率从 $0.6$ 变成 $0.61$。重新抽一次——**抽出来的还是 A**。输出没有任何变化，所以

$$
\frac{\partial y}{\partial \theta}=0
$$

（只有把概率调到足够大或足够小，让采样结果真的翻转成 B，$y$ 才会"跳"一下。但这种跳变是离散的，**跳变点上没有导数**。）


所以，奖励能告诉我们"这次做得好不好"，但**不能告诉我们"参数该往哪更新"**。


到这里，我们就要引入**策略梯度：把"分数"变成"梯度方向"**

关键一步是**把期望展开成求和**。期望本来就是一个加权和：

$$
J(\theta)=\mathbb{E}_{y\sim\pi_\theta}\big[R(y)\big]=\sum_{y}\pi_\theta(y)\,R(y)
$$


现在对两边求梯度。注意 $R(y)$ 对 $\theta$ 来说是常数（断点一已经说明了这一点），所以它原样不动，只有 $\pi_\theta(y)$ 需要求导：

$$
\nabla_\theta J(\theta)=\sum_{y}\nabla_\theta\pi_\theta(y)\,R(y)
$$

到这里问题变成了"**概率本身怎么随参数变化**"，也就是要算 $\nabla_\theta\pi_\theta(y)$。直接算它在数值上很不方便，于是用恒等式换个写法：

$$
\nabla_\theta\pi_\theta(y)=\pi_\theta(y)\,\nabla_\theta\log\pi_\theta(y)
$$

> **这个恒等式从哪来？** 对 $\log\pi_\theta$ 用链式法则：
>
> $$\nabla_\theta\log\pi_\theta(y)=\frac{1}{\pi_\theta(y)}\nabla_\theta\pi_\theta(y)$$
>
> 两边同乘 $\pi_\theta(y)$ 就得到上式，代回去：

$$
\nabla_\theta J(\theta)=\sum_{y}\pi_\theta(y)\,\nabla_\theta\log\pi_\theta(y)\,R(y)
$$

现在的求和式又变成了一个期望——因为每一项都乘着 $\pi_\theta(y)$：

$$
\nabla_\theta J(\theta)=\mathbb{E}_{y\sim\pi_\theta}\Big[\nabla_\theta\log\pi_\theta(y)\,R(y)\Big]
$$

**这就是策略梯度。** 回头看，它把两个断点都绕开了：

- $\nabla_\theta\log\pi_\theta(y)$：模型自己的对数概率，**完全可导**。
- $R(y)$：只当作一个**乘在前面的常数权重**，从头到尾没对它求过导。

所以虽然奖励和采样都不可导，我们依然能得到一个可用的梯度方向：**采样一条回答、打个分、把分数乘到对数概率的梯度上**。

**换一个角度理解：不通过"动作"反传，而通过"概率"反传。**

假设模型对三个 token 的概率是 `[0.6, 0.3, 0.1]`，这次抽中了第一个，最后得分 $R=10$。

直接反向传播想说的是："抽中第一个让回报变高了，所以要让第一个更容易被抽中"——可"抽中第一个"是个离散结果，**没法求导**。

策略梯度换了个说法：

> 我不管"抽中第一个"这个动作怎么求导。
> 我只知道：刚才那个状态下，第一个 token 的概率是 $0.6$。
> 既然这次回报高，我就沿着 $\nabla_\theta\log 0.6$ 的方向调参数，让以后它的概率更大。

也就是说：梯度是**通过"概率"传回网络的，不是通过"动作"**。

**落到语言模型上**：一整段回答的似然是每个 token 概率的连乘 $\pi_\theta(y)=\prod_t\pi_\theta(y_t\mid y_{<t})$，取对数后变成求和 $\log\pi_\theta(y)=\sum_t\log\pi_\theta(y_t\mid y_{<t})$。所以上面的梯度会自然展开成**逐 token** 的形式：

$$
\nabla_\theta J(\theta)=\mathbb{E}\left[\sum_{t}\nabla_\theta\log\pi_\theta(y_t\mid y_{<t})\,R(y)\right]
$$

注意 **$R(y)$ 是整段回答的一个分数，却乘在了每一个 token 的梯度上**——这正是 1.1 节说的"整段一个分"要分摊到每个 token。

看到这里，其实我们已经有了利用策略梯度训练模型的一个闭环，但实际上其中还可以再改进一点：

一是**奖励通常非负**（答对 1、答错 0），所以每条回答拿到的权重都 $\ge 0$，梯度只会**提高**被采样回答的概率，永远不会主动压低它。答错时权重恰好是 0，既没抬高也没压低——这次采样白费了，模型什么也没学到。

二是**原始奖励的方差太大**。它混着"题目难度"这个与回答质量无关的成分：难题上所有回答得分都低，简单题上都高。直接用 $R$，梯度分不清"这条回答好"还是"这道题简单"。

**解决办法是减掉一个基线（baseline）**，得到**优势** $\hat A=R-\text{baseline}$。设基线是 0.5（大致是当前平均分）：

| 情况 | 奖励 $R$ | 优势 $\hat A=R-0.5$ | 梯度效果 |
| --- | --- | --- | --- |
| 答对 | $1$ | $+0.5$ | 提高这条回答里各 token 的概率 |
| 答错 | $0$ | $-0.5$ | **降低**这条回答里各 token 的概率 |

优势的含义就是：$\hat A>0$ 比平均好，**提高**概率；$\hat A<0$ 比平均差，**降低**概率。

减掉基线后，答错拿到的是**负**权重，模型才会主动压低它；同时题目难度这一成分被消掉，比较只发生在同一道题内部。

所以基线的真正作用是**降低梯度方差、让信号更干净**。

### 1.4 Actor-Critic：最重要的策略梯度框架

**但随之就有个问题：基线应该怎么设置？** 设得太低，答错的回答也会拿到正优势，被错误地鼓励；设得太高，答对的回答反而被压低。所以，**基线应该等于"在当前状态下，平均能拿到多少分"**。

可问题是：这个"平均分"我们事先并不知道。**解决办法是再训一个模型去预测它。** 于是就有了 Actor-Critic 里的两个角色：

| 角色 | 是什么 | 干什么 |
| --- | --- | --- |
| **Actor**（演员） | 策略模型 $\pi_\theta$ | 决定"该输出什么 token"，也就是我们最终要的语言模型 |
| **Critic**（评论家） | 价值模型 $V_\phi$ | 预测"从这里往后大概能拿多少分"，给 Actor 提供基线 |

- **Actor 学"怎么做"**：用优势 $\hat A=R-V_\phi(s)$ 当权重，提高好回答的概率。
- **Critic 学"怎么评"**：它的训练标签就是**采样完之后真实拿到的回报 $R$**——回答生成完、奖励算出来，$R$ 就是一个已知的数，不需要额外标注。于是 Critic 退化成一个普通的回归问题：用均方误差 $L_{critic}=\big(V_\phi(s)-R\big)^2$ 做梯度下降，**把自己的预测往实际回报的方向拉**。

> 上面这个写法是**最简化的 Critic 版本**：拿到最后奖励时，可以直接拿最终回报当标签。标准 PPO 里每个位置拟合的是**从该位置往后的回报目标**——可以取完整回报，也可以用自举（bootstrap）算，具体看实现。2.4 节讲 GAE 时会再回到这一点。

> **Actor-Critic 不是某一个具体算法，而是一类框架。** 它只规定了"用 Actor 选动作、用 Critic 打分"这个骨架。在这个骨架上怎么实现，就派生出不同算法：A2C、A3C、TRPO、SAC，以及本文要讲的 **PPO**。

到这里，策略梯度加上 Critic，已经可以落地成一个可执行的流程：

```text
1. 采样：Actor 生成一批回答
2. 打分：给每条回答评分，Critic 预测基线，算出优势
3. 更新：
   - Actor：用优势当权重，提高好回答的概率、压低坏回答的概率
   - Critic：拿"实际拿到的回报 R"当标签，用均方误差把预测值 V(s) 往 R 拉
4. 回到第 1 步
```

这就是最朴素的 Actor-Critic 算法。

**但普通 Actor-Critic 有两个问题**：

1. **样本效率低**：第 1 步的采样成本很高，但第 3 步却只用一次就把这批数据扔了，过于浪费。
2. **更新可能太猛**：策略一步走太大，性能可能突然崩掉，而且很难恢复。

## 2. PPO：用裁剪控制更新幅度

PPO（Proximal Policy Optimization，近端策略优化）来自 2017 年的论文，是 RLHF 时代最主流的算法。

> **PPO 仍然是策略梯度方法，也仍然用 Actor-Critic 架构。**

它只是在 1.4 节那个 Actor-Critic 流程上，加了两个改进：

1. **重要性采样**：允许用旧策略采的数据来更新新策略，从而**同一批数据能多学几遍**；
2. **裁剪**：限制新策略不要偏离旧策略太远，给更新装一个**限速器**。

### 2.1 PPO 的四个模型

| 模型 | 作用 | 训练中是否更新 |
| --- | --- | --- |
| **Policy Model**（策略模型 / Actor） | 就是我们要训练的语言模型，负责生成回答 | ✅ 更新 |
| **Value Model**（价值模型 / Critic） | 预测"从这里往后大概能拿多少分"，用来算优势 | ✅ 更新 |
| **Reference Model**（参考模型） | SFT 后模型的冻结副本，用来算 KL 惩罚 | ❌ 冻结 |
| **Reward Model**（奖励模型） | 给整段回答打分，替代人类打分 | ❌ 冻结 |


前两个（Actor 和 Critic）就是 1.4 节讲的 Actor-Critic 框架；后两个（Reference 和 Reward）是 RLHF 特有的补充。逐个说清楚：

**Policy Model** 是最终要部署的那个语言模型。它从 SFT 模型初始化，训练全程都在更新。

**Reward Model** 解决的是"**人类没法实时打分**"。PPO 每轮要生成成千上万条回答，不可能每条都找人评分。所以先用一批人类偏好数据（同一个问题的两个回答，人标注哪个更好）训练一个打分器，之后就用它自动给回答打分。

**Reference Model** 解决的是"**模型会钻奖励模型的空子**"。奖励模型只是个近似，它会有盲区。如果放任策略一味追高分，模型很快会学会输出"看起来高分但语言已经崩坏"的文本——也就是 **reward hacking**。所以保留一份 SFT 模型的冻结副本，用 KL 散度约束策略别偏离它太远。

**Value Model** 解决的是"**优势里的基线从哪来**"。这就是 1.4 节的 Critic：优势 $\hat A=R-V$，那个 $V$ 就是它给的——它预测的是"看到当前这段前缀，这条回答最终能拿多少分"。

> **这里有个关键区别，也是后面 GRPO 的切入点**：Reward Model 只在**整段回答结束后**输出一个标量分数，而 Value Model 要给**每个 token** 估计一个价值。这个"粒度不匹配"，正是 GRPO 想省掉 Value Model 的原因。

四个模型在流程里的关系是这样的（先看上半部分，下半部分的 GRPO 留到第二篇再讲）：

**PPO 的四个阶段**

把上面四个模型串起来，PPO 在 RLHF 里其实分四个阶段，前两个是准备，后两个是循环：

![PPO 的四个模型与四个阶段](/assets/img/rl/ppo-pipeline.webp){: .qwen-figure width="1785" height="942" }

图 2 · 上面一行是四个模型及其更新状态（Actor 和 Critic 训练中更新，Reference 和 Reward 全程冻结）；下面一行是四个阶段，阶段 0 只做一次，阶段 1–3 循环，且同一批数据可以多轮更新。

```text

    ↓
阶段 2 · Evaluation：Reward Model 给回答打分

    ↓
    回到阶段 1
```

对照 1.4 节那个 Actor-Critic 循环，可以看到 PPO 多出来的东西：**阶段 0 多训练了 Reward Model**（解决"没人实时打分"），**阶段 3 多训了一个 Value Model**（解决"基线从哪来"）。代价是显存和工程复杂度都上去了——这也是后面几个算法想优化掉的部分。

### 2.2 重要性采样

正如1.4 节说的第一个问题：Actor-Critic 样本效率太低。所以一个自然想法是**同一批数据多做几次梯度更新**（比如切成 4 份小 batch）——这在监督学习里很正常，同一批图片当然可以训练好几个 epoch。但在 RL 里没这么自由：这批数据是**旧模型**采的，参数一更新，产生数据的分布就和当前策略对不上了。拿"旧分布采的样本"直接去估"新策略下的期望"，结果会偏，这就是 **off-policy** 问题。

**为了解决off-policy 的问题，我们就要修正权重。**

假设旧策略采了 100 条回答，其中 10 条是"先列方程、再求解"这种写法——也就是说，这种写法在旧策略下的出现概率是 $0.1$。

但我们现在要评估的是**新策略**。如果新策略已经更偏爱这种写法，概率变成了 $0.2$，那这 10 条样本在"新策略的世界里"就该当成 20 条来算——因为这种写法出现的可能性翻倍了。所以每条样本要乘一个 $0.2/0.1=2$ 的权重。

反过来，如果新策略不那么喜欢某种写法（旧 $0.2$、新 $0.1$），那每条就只能算半条，权重是 $0.5$。

这个倍数就是**重要性权重**：**同一个样本，在新旧两个分布里的出现概率之比。**

写成公式（用 $y$ 表示一整条回答）：

$$
\mathbb E_{y\sim\pi_{\text{new}}}\big[f(y)\big]=\mathbb E_{y\sim\pi_{\text{old}}}\left[\frac{\pi_{\text{new}}(y)}{\pi_{\text{old}}(y)}\,f(y)\right]
$$

左边是我们真正想求的（需要从新模型重新采样，太贵），右边是手上就有的（旧样本 + 一个权重）。**这就是"用旧数据评估新策略"。**

不过真正训练时，PPO 并不是拿整条回答算一个比率，而是**逐 token 算**——因为梯度本来就是逐 token 落到语言模型上的。所以比率定义在 token 上，这就是 PPO 里最重要的量——**概率比率**：

$$
r_t(\theta)=\frac{\pi_\theta(y_t\mid x,\ y_{<t})}{\pi_{\theta_{\text{old}}}(y_t\mid x,\ y_{<t})}
$$

分子是**新模型**在第 $t$ 个位置吐出这个 token 的概率，分母是**旧模型**的概率；$x$ 是 prompt，$y_{<t}$ 是已经生成好的前 $t-1$ 个 token。

这里要澄清一点：整条回答的重要性比率其实是各 token 比率的**连乘** $\prod_t r_t$。PPO 并不拿它做一次严格的分布修正。所以重要性采样在这里的作用是"给出一个可优化的目标形式"，并不能"保证估计无偏"。

| 情况 | 含义 | 这条样本该怎么处理 |
| --- | --- | --- |
| $r_t=1$ | 新旧策略完全一样（训练刚开始必然如此） | 原样使用 |
| $r_t>1$ | 新策略更想让这个 token 出现（旧 $0.5$、新 $0.8$，则 $r_t=1.6$） | 放大它的作用 |
| $r_t<1$ | 新策略不那么想让这个 token 出现 | 缩小它的作用 |

有了比率，就能用旧数据写出新策略的目标：

$$
L^{CPI}(\theta)=\hat{\mathbb E}_t\left[r_t(\theta)\,\hat A_t\right]
$$

这里的 $\hat A_t$ 就是 **1.3 节定义的那个优势**（$\hat A=R-\text{基线}$）。唯一的变化是加了下标 $t$：1.3 节是**整条回答共用一个优势**，而 PPO 要逐 token 算梯度，所以需要知道"第 $t$ 个 token 有多好"这个**逐 token** 的优势。至于它具体怎么算出来（GAE），2.4 节再讲，这里先当作已知量。

于是这个式子说的就是：**好 token 按比率放大，差 token 按比率缩小**。$L^{CPI}$ 里的 CPI 是"保守策略迭代"（Conservative Policy Iteration）的缩写，是 PPO 之前的老做法。

### 2.3 裁剪：给更新装一个限速器

$L^{CPI}$ 有个隐患：**比率可以无限大**。

设想某个 token 的优势是正的（说明它是好 token），那优化器就会一路推高它的概率——从 $0.01$ 推到 $0.9$，比率变成 90 倍。但这里有个致命问题：**这个比率是用旧数据算出来的**，我们用旧策略的比值估计新策略本身就存在着偏差，如果不加以控制，模型会越训越偏。

PPO 的做法很直接：**给比率做一次裁剪**，把它夹在 $[1-\epsilon,\,1+\epsilon]$ 之间（$\epsilon$ 通常取 $0.2$，也就是 $[0.8,\,1.2]$）加以控制。

$$
L^{CLIP}(\theta)=\hat{\mathbb E}_t\left[\min\Big(r_t(\theta)\hat A_t,\ \operatorname{clip}\big(r_t(\theta),\,1-\epsilon,\,1+\epsilon\big)\hat A_t\Big)\right]
$$

其中：

- $r_t(\theta)$：概率比率，就是上面那个"新概率 ÷ 旧概率"。
- $\operatorname{clip}(x,a,b)$：把 $x$ 夹在 $[a,b]$ 里。比 $a$ 小就当成 $a$，比 $b$ 大就当成 $b$。
- $\hat A_t$：优势，这里精确到每个 token。

整个式子就是在算出两个候选值，取小的：

1. $r_t\hat A_t$——不裁剪的原始目标；
2. $\operatorname{clip}(r_t,1-\epsilon,1+\epsilon)\hat A_t$——把比率夹住之后再算的目标。

| 情况 | 比率在区间内 | 比率越界后 |
| --- | --- | --- |
| 优势 $>0$（好 token，想提高概率） | 继续涨 | 涨到 $1+\epsilon$ 倍就**不再奖励** |
| 优势 $<0$（差 token，想降低概率） | 继续降 | 降到 $1-\epsilon$ 倍就**不再惩罚** |

> **为什么取 $\min$ 而不是 $\max$？** 因为优势为负时，数值大小和符号会反过来。取 $\min$ 的效果是：**只在"更有利的方向"上更新**——优势为正、比率超过 $1+\epsilon$ 时，再放大比率也不加分；优势为负、比率跌破 $1-\epsilon$ 时，再缩小比率也不减分。同时，反方向的越界（比如优势为正但比率掉到 $1-\epsilon$ 以下）却仍然有梯度，会把它往回推。

**把目标函数写全**

上面写的是"单个 token"的情况。真正训练时，PPO 是在一条回答内部对所有 token 求平均，再对一批回答求平均：

$$
J^{PPO}(\theta)=\mathbb E_{x\sim\mathcal D,\ y\sim\pi_{\theta_{\text{old}}}}\left[\frac{1}{\lvert y\rvert}\sum_{t=1}^{\lvert y\rvert}\min\Big(r_t(\theta)\hat A_t,\ \operatorname{clip}\big(r_t(\theta),1-\epsilon,1+\epsilon\big)\hat A_t\Big)\right]
$$

逐个对回语言模型：

- $x\sim\mathcal D$：从训练集里抽一个 prompt。
- $y\sim\pi_{\theta_{\text{old}}}$：用**旧模型**生成一条回答，这就是"同一批数据"。
- $\frac{1}{\lvert y\rvert}\sum_{t=1}^{\lvert y\rvert}$：对这条回答里的所有 token 求平均（**注意这个"先按长度归一化"的位置**，第二篇讲 DAPO 时会用到）。
- 方括号里的 $\min(\cdot,\cdot)$：就是上面那个裁剪目标。

实际训练还会再加一项 **KL 惩罚** $\mathbb E\big[-\beta D_{KL}[\pi_\theta\,\lVert\,\pi_{\text{ref}}]\big]$，作用是拉住模型，别为了刷分把基础能力练废（$\beta$ 是这一项的权重）。

这就是 PPO 在语言模型上**真正在优化的东西**。

### 2.4 Critic 怎么训：从 TD 目标到 GAE

目标函数里还剩最后一个量没交代：$\hat A_t$。它由价值模型算出来，所以这一节要回答的其实是——**价值模型本身怎么训练？**
它学的东西很朴素：给定当前这段前缀，往后大概能拿多少分。训练方式也和回归一样，**让预测值逼近一个"目标值"，用均方误差**：

$$
L_{critic}(\phi)=\mathbb E_t\Big[\big(V_t-\text{Target}_t\big)^2\Big],
\qquad V_t:=V_\phi(x,\,y_{<t})
$$

所以关键只剩一个问题：**Target 怎么定？** 两种最朴素的选择：

| 目标 | Target 取什么 | 特点 |
| --- | --- | --- |
| **TD 目标** | $R_t+\gamma V_{t+1}$——这一步实际拿到的奖励，加上价值模型对下一步的估计 | 方差小，但拿**自己的预测**当一部分标签（叫"自举"，bootstrap），预测不准就会把偏差带进来 |
| **MC 目标** | $G_t$——走完整条回答后的累计回报，全部用实际发生的奖励 | 没有自举偏差，但一条回答的运气成分全算进去，方差大 |

**PPO 用的是两者的折中：GAE。**
先定义**时序差分误差**（TD 误差）：

$$
\delta_t=\underbrace{R_t+\gamma V_{t+1}}_{\text{实际拿到的}}-\underbrace{V_t}_{\text{原本预期的}}
$$

**它就是"这一步比我预期的好多少"。** GAE 再把这些 $\delta$ 按权重累加起来：

$$
\hat A_t^{GAE(\gamma,\lambda)}=\sum_{l=0}^{\infty}(\gamma\lambda)^l\,\delta_{t+l}
$$

$\lambda$ 就是 TD 和 MC 之间的旋钮：

- $\lambda=0$：只剩 $\delta_t$，几乎全靠价值模型的预测——方差小，但预测不准就直接带偏。
- $\lambda=1$：求和会望远镜式抵消，正好变成 $G_t-V_t$（完整回报减基线）——偏差小，但方差大。

Critic 的更新目标，在很多 PPO 实现中，就是**让价值模型的预测 $V_\phi(s_t)$ 去拟合基于 GAE 构造出的 n-step 回报 $G_t^{(n)}$**：

$$
L_{critic}(\phi)=\mathbb E_t\Big[\big(V_\phi(s_t)-G_t^{(n)}\big)^2\Big]
$$

这里的 $s_t$ 指"prompt + 前 $t$ 个 token"这个状态，$V_\phi(s_t)$ 就是前面那个 $V_t$——写成函数形式只是为了点明它由参数 $\phi$ 决定。

$G_t^{(n)}$ 可以理解为：**往前看 $n$ 步的实际奖励，加上第 $n$ 步时 Critic 对那个状态的估值**。$\lambda$ 在这里起的就是调平衡的作用（通常取 $0.95$ 左右），让 Critic 的学习信号更稳定。

但是这种方法在 LLM 场景下仍然面临着错配问题：在传统 RL（如游戏、机器人）中，每一步动作都有即时奖励 $R_t$，Critic 可以逐 token 地学习"这一步好不好"。但在 LLM 偏好对齐中，**奖励模型通常只对整个完整回答给出一个最终分数**。这就导致 Critic 面临一个错配：

- **奖励是稀疏的、单点的**：一个几十上百 token 的回答，只有一个标量奖励。
- **Critic 却需要对每个中间 token 位置估计价值**：它被要求预测"从这个半截句子继续下去，最终能得多少分"。

这种"**单点奖励 vs. 全程估值**"的错配，使得 Critic 的预测目标 $G_t^{(n)}$ 本身就**极不可靠**——它很大程度上依赖于 Critic 自己对未来的、尚未发生的状态的估计，误差会自我累积。这也是为什么训练一个准确的价值网络在 LLM 场景下格外困难，以及后来 GRPO 选择**干脆去掉 Critic** 的核心原因。


### 2.5 和 A2C 的对比

PPO 经常被看作 **A2C 的稳定改进版**。两者的差别如下：

| 对比项 | A2C（普通 Actor-Critic） | PPO |
| --- | --- | --- |
| 架构 | Actor-Critic | Actor-Critic |
| 数据使用 | 通常只用一次 | 同一批数据多轮 |
| 更新限制 | 无显式限制 | 裁剪或 KL 惩罚 |
| 策略偏离 | 可能很大 | 限制在旧策略附近 |
| 样本效率 | 较低 | 较高 |
| 稳定性 | 一般 | 更好 |

**一个常见误解**：既然 PPO 能用旧数据多轮更新，它是不是变成 off-policy 了？

**不是。** 裁剪的作用正是把新策略**固定在旧策略附近**——数据虽然来自旧策略，但因为两者足够接近，用它估计新策略仍然是可靠的。所以 PPO 是 **on-policy（或近似 on-policy）**算法，这也是它必须不断重新采样、而不能像 DPO 那样反复用同一份固定数据的原因。
