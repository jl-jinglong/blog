<div class="qwen-note" markdown="1">

近几年，大语言模型的上下文窗口从 2K、4K 扩展到 32K、128K，甚至 1M token。表面上看，这只是把配置文件中的最大长度改大；但真正的问题至少有四个：

1. **位置编码是否见过这么远的位置**；
2. **注意力和 KV cache 是否承担得起这么长的序列**；
3. **模型是否在训练中学会了使用远距离信息**；
4. **模型能否在有限显存和带宽下完成预填充与逐 token 解码**。

因此，“支持 128K”并不等于“能有效理解 128K”。一个模型可能能够接收 128K 个 token，却只在开头和结尾附近有效；也可能通过 RoPE 外推让位置索引不报错，但没有获得稳定的长距离检索能力。

本文把上下文扩展拆成几条技术路线：

```text
位置/频率扩展      → 让模型在更长位置上保持可用的相对位置信号
注意力模式改造     → 让每个 token 不必与所有 token 做完整交互
长上下文训练       → 让模型真正学会使用远距离信息
记忆与 KV cache     → 让流式输入或超长历史不必全部保留
系统并行与内核优化  → 让完整或稀疏注意力能够在硬件上运行
```

其中，**Position Interpolation、NTK-aware、Dynamic NTK、YaRN、LongRoPE**主要解决位置外推；**Window Attention、Longformer、DCA**主要改变注意力的可见范围或相对位置组织；**Transformer-XL、StreamingLLM、Infini-attention**则引入跨段记忆或压缩记忆；**FlashAttention、Ring Attention、MInference**主要解决计算和显存问题。

## 1. 先把几个“长度”分开

设模型训练时的最大序列长度为 $L$，希望推理时使用的目标长度为 $L'$，扩展倍率为：

$$
s = \frac{L'}{L}.
$$

实际讨论中至少有四个长度概念：

| 名称 | 含义 | 例子 |
| --- | --- | --- |
| 训练长度 | 预训练或微调时真正出现过的最大序列长度 | Qwen-1 约 2K；Qwen2 末期 32K |
| 配置长度 | 模型配置和推理框架允许的最大位置数 | `max_position_embeddings=32768` |
| 外推长度 | 借助位置缩放或注意力重构，在未重新长训时尝试的长度 | Qwen2 由 32K 外推到约 128K |
| 有效理解长度 | 在检索、总结、问答等任务上仍然可靠的长度 | 需要 NIAH、RULER、LongBench 等评测 |

配置长度只是“能不能把输入送进去”；有效理解长度才是“模型是否真的使用了这些内容”。

## 2. 为什么上下文变长会变难？

### 2.1 位置编码遇到了训练分布外的位置

先看标准的 causal self-attention：

$$
\operatorname{Attention}(Q,K,V)
=\operatorname{softmax}\left(\frac{QK^\top}{\sqrt{d_h}}\right)V.
$$

没有位置编码时，注意力只能比较 token 内容，无法区分顺序。RoPE 将 query 和 key 的每一对维度看成二维平面，并在位置 $m$ 旋转一个角度。第 $i$ 个频率可以写成：

$$
\omega_i=b^{-2i/d},
\qquad
\phi_{m,i}=m\omega_i,
$$

其中 $b$ 是 RoPE 的 base frequency，$d$ 是 head dimension。旋转后的 QK 点积具有相对位置性质：它主要依赖 $m-n$，而不是两个绝对位置分别是多少。

问题在于，模型训练时只见过 $0\le m<L$。当推理位置进入 $L$ 之外，模型面对的是没有训练过的相位组合。对高频维度来说，轻微的位置变化会造成很快的相位变化；直接把位置继续外推，容易造成注意力分数剧烈振荡。

![直接外推与位置插值的直观对比](/assets/img/context/pi-overview.webp){: .qwen-figure width="760" }

<div class="qwen-caption">图 1 · Position Interpolation 的核心直觉：直接外推会进入未见位置范围，位置插值则把目标区间压回预训练范围。来源：[Position Interpolation 原论文，Figure 1，PDF p.2](https://arxiv.org/abs/2306.15595)。</div>

原论文进一步展示了为什么直接外推不稳定：在训练区间外，拟合得到的 attention score 可能突然爆炸；而插值后的曲线仍然落在训练时见过的范围附近。

![直接外推的注意力分数不稳定](/assets/img/context/pi-instability.webp){: .qwen-figure width="760" }

<div class="qwen-caption">图 2 · extrapolation 与 interpolation 的 attention score 对比。来源：[Position Interpolation 原论文，Figure 2，PDF p.4](https://arxiv.org/abs/2306.15595)。</div>

### 2.2 全注意力的计算和缓存成本

如果序列长度为 $N$，标准注意力需要计算一个 $N\times N$ 的相关性矩阵，时间和中间显存大致随 $O(N^2)$ 增长。自回归生成时，还要把历史 token 的 K/V 保存为 KV cache，其存储量大致随 $O(N)$ 增长。

因此，长上下文有两个不同的硬件问题：

- **Prefill**：第一次处理整段输入，主要受 $N^2$ 的注意力计算影响；
- **Decode**：逐 token 生成，主要受 KV cache 容量和内存带宽影响。

FlashAttention 可以减少注意力中间矩阵的显存读写，Ring Attention 可以把序列切到多张卡上，但它们不会自动教会模型理解更长的位置。后文会把“语义扩展”和“系统加速”分开。

### 2.3 模型并没有因为窗口变大就自动学会长距离依赖

在训练中从未出现过 100K token 的样本时，模型可能会：

- 只关注最近的局部上下文；
- 对中间内容出现明显的 `lost in the middle`；
- 在长文档中忘记前文的实体、约束或主题；
- 能检索一个孤立的 passkey，却不会完成需要多处信息联合的推理。

所以长上下文扩展至少要同时考虑**位置分布、可见范围、训练数据和评测方式**。

## 3. 位置和频率扩展

这一类方法尽量保持 Transformer 主干不变，主要修改 RoPE 的位置索引、频率或注意力分数。

### 3.1 Position Interpolation：把新位置压回旧范围

**Position Interpolation（PI）**的想法很直接：目标长度是 $L'=sL$ 时，不让模型看到 $0$ 到 $L'-1$ 的新位置，而是把位置缩小到原来的范围：

$$
m' = \frac{m}{s}
\quad\text{或写成}\quad
f'(x,m)=f\left(x,\frac{mL}{L'}\right).
$$

这样，目标序列中的最后一个 token 仍然对应原模型接触过的位置 $L$ 附近。它解决的是“位置落到训练分布外”的问题，而不是注意力的 $O(N^2)$ 成本。

PI 的优点是结构简单、几乎不改变模型；缺点是所有位置都被压缩，近距离和远距离的相对分辨率都会变小，通常需要少量长上下文微调来恢复性能。原论文在 LLaMA 上用很少的微调步骤将 2K 扩展到 32K。[Position Interpolation](https://arxiv.org/abs/2306.15595)

### 3.2 NTK-aware scaling：不要把所有频率等比例压缩

PI 对每个 RoPE 维度使用同一个缩放倍率，但 RoPE 的不同维度本来就对应不同频率。**NTK-aware scaling**的出发点是：高频维度负责分辨局部位置，低频维度负责更长距离；如果所有频率都等比例拉伸，会损失局部位置信息。

一种常见写法是把 RoPE base 从 $b$ 改为：

$$
b' = b\,s^{d/(d-2)}.
$$

这样会更大幅度地减慢低频维度，高频维度相对保留更多原来的变化速度。NTK-aware 最初主要以社区实现和工程文章的形式传播，YaRN 论文对它进行了系统整理和比较，因此写作时最好把它称为一种方法，而不要把它包装成一篇独立、统一的正式论文。

### 3.3 Dynamic NTK：让缩放倍率随当前长度变化

固定 NTK-aware scaling 需要提前知道目标长度；**Dynamic NTK**则根据当前序列长度动态调整缩放倍率：

$$
s(n)=\max\left(1,\frac{n}{L}\right).
$$

当当前长度 $n\le L$ 时保持原来的 RoPE；只有超过训练长度后才增加缩放。这样短上下文不会因为为了长上下文而被过度修改，长上下文则逐步进入扩展模式。

动态缩放与 KV cache 有一个容易忽略的实现问题：如果每次长度变化都会改变历史 token 的 RoPE，已经缓存的旋转后 K 可能不再对应当前频率。实现需要缓存旋转前的 K，或者同步更新缓存。因此，Dynamic NTK 不只是“把一个 if 条件加到 RoPE 上”。

Qwen-1 的报告明确使用了 NTK-aware interpolation 和 dynamic NTK-aware interpolation，并说明 dynamic NTK 会随长度分块改变 scale；它还配合 LogN scaling 和分层窗口注意力，把训练长度 2K 的模型推理扩展到 8K 以上。[Qwen Technical Report](https://arxiv.org/abs/2309.16609)

### 3.4 LogN-Scaling：稳定注意力熵，而不是修改位置

LogN-Scaling 经常和 NTK-aware 一起出现，但它不是位置编码方法。它直接调整 attention logits 的尺度，使序列变长时 softmax 不至于越来越尖锐或越来越平。

可以用一个简化形式表示：

$$
Q' = Q\cdot \frac{\log n}{\log L},
\qquad
\frac{Q'K^\top}{\sqrt{d_h}}
=\frac{\log n}{\log L}\frac{QK^\top}{\sqrt{d_h}}.
$$

其中 $L$ 是训练长度，$n$ 是当前上下文长度。Qwen-1 的实现是在 query 上乘以 LogN 因子，因此等价于缩放 QK logits；它不是把 value 乘上一个系数。

这类缩放解决的是**注意力分布随长度变化的数值稳定性**，不能单独解决 RoPE 的未见位置，也不能降低 $O(N^2)$ 的计算量。Qwen-1 的实验中，dynamic NTK、LogN 和窗口注意力组合后，长序列困惑度比只使用原始 RoPE 稳定得多。

### 3.5 YaRN：NTK-by-parts + attention scaling

**YaRN（Yet another RoPE extensioN）**可以看作对 PI 和 NTK-aware 的组合式改进。它包含两个关键部分：

1. **NTK-by-parts interpolation**：按照 RoPE 维度对应的波长决定缩放程度。高频维度尽量不动，低频维度进行更多插值，中间频率使用平滑过渡；
2. **Attention scaling**：对 attention logits 加入长度相关的温度修正，补偿插值后注意力熵的变化。

![YaRN 与其他插值方法的关系](/assets/img/context/yarn-summary.webp){: .qwen-figure width="760" }

<div class="qwen-caption">图 3 · YaRN 原论文对 RoPE、PI、NTK-aware、NTK-by-parts 和 attention scaling 的关系概览。来源：[YaRN 原论文，Figure 1，PDF p.2](https://arxiv.org/abs/2309.00071)。</div>

对于扩展倍率 $s$，YaRN 论文给出了一种 attention temperature 的经验设置，常见写法为：

$$
\sqrt{\frac{1}{t}}=1+0.1\ln s.
$$

YaRN 的价值不只是“换一个 RoPE 公式”，而是同时处理位置频率和注意力分布。它可以用很少的长上下文微调步数获得较大的窗口扩展，也可以与 Dynamic NTK 组合进行推理时扩展。[YaRN](https://arxiv.org/abs/2309.00071)

### 3.6 ABF：训练中的 RoPE base 调整

**Adjusted Base Frequency（ABF）**是另一条经常和 Qwen 后续版本一起出现的路线：在继续预训练长序列时增大 RoPE base，例如从 10,000 调整到 1,000,000 或更大，使旋转角度变小、远距离位置变化更平滑。

ABF 和 NTK-aware 的区别在于：NTK-aware 常被用作训练无关或少量微调的频率缩放；ABF 通常属于**长上下文继续预训练的一部分**，需要配合长文本数据让模型重新适应新的位置分布。Qwen2、Qwen2.5 和 Qwen3 的长上下文训练阶段都使用了类似的 base frequency 调整。[Effective Long-Context Scaling of Foundation Models](https://arxiv.org/abs/2309.16039)

### 3.7 LongRoPE：为每个 RoPE 维度搜索不同的缩放

PI、NTK-aware 和 YaRN 都使用人为设计的缩放规则；**LongRoPE**进一步搜索每个 RoPE 维度的非均匀缩放因子，同时保留部分初始 token 的原始位置。

![LongRoPE 的非均匀位置插值](/assets/img/context/longrope.webp){: .qwen-figure width="760" }

<div class="qwen-caption">图 4 · 直接外推、线性位置插值与 LongRoPE 的非均匀位置插值对比。来源：[LongRoPE 原论文，Figure 2，PDF p.3](https://arxiv.org/abs/2402.13753)。</div>

LongRoPE 的训练流程是渐进式的：先扩展到 256K，再继续扩展到约 2M；同时用短上下文回调微调恢复原始 4K/8K 能力。它说明了一个趋势：**越大的扩展倍率，越需要非均匀的频率设计和渐进式训练，而不是单个全局缩放系数。**[LongRoPE](https://arxiv.org/abs/2402.13753)

### 3.8 其他位置方案：ALiBi、XPos 与 Llama 系列的 scaling

- **ALiBi**：不使用显式位置向量，而是在 attention logits 中加入各个 head 不同斜率的线性距离惩罚。它简单、没有位置表，但表达的距离关系较单一。[ALiBi](https://arxiv.org/abs/2108.12409)
- **XPos**：在 RoPE 基础上对 Q/K 做互补的长度缩放，试图保持远距离 attention 的分辨率，并结合 blockwise causal attention。[XPos](https://arxiv.org/abs/2212.10554)
- **Llama 3.1 等模型的 RoPE scaling**：使用分频段的频率缩放和更长上下文继续训练，属于“位置缩放 + 长上下文训练”的工程组合，不应只理解成改一个 `max_position_embeddings`。

## 4. 注意力模式：不让每个 token 看完整的 $N\times N$

位置插值主要解决“位置怎么表示”；注意力模式则解决“哪些 token 彼此交互”。这类方法通常降低计算成本，但也会牺牲一部分全局可见性。

### 4.1 Sliding Window Attention：固定窗口换取线性成本

**Sliding Window Attention（SWA）**让位置 $i$ 只关注附近宽度为 $w$ 的 token：

$$
j\in[i-w+1, i].
$$

复杂度从 $O(N^2)$ 变为近似 $O(Nw)$。多层堆叠后，信息仍然可以逐层传播到更远位置，但单层不会直接访问整段文本。

Longformer 将滑动窗口、扩张窗口和全局 token 组合起来；Mistral 7B 则使用窗口大小 4096 的 SWA 和滚动 KV cache。它们主要解决计算和缓存，不等于模型在没有长训的情况下自动获得全局 128K 理解。

![Longformer 的几种注意力模式](/assets/img/context/longformer-patterns.webp){: .qwen-figure width="760" }

<div class="qwen-caption">图 5 · Full、sliding、dilated 和 global+sliding attention pattern。来源：[Longformer 原论文，Figure 2，PDF p.3](https://arxiv.org/abs/2004.05150)。</div>

### 4.2 分层窗口注意力：不同层使用不同窗口

Qwen-1 的报告没有为每一层公开固定的窗口数字，但给出了一个重要观察：低层更依赖局部信息，可以使用较短窗口；高层需要整合更远的语义，可以使用较长窗口。

这比所有层使用同一个窗口更灵活，但窗口表本身需要实验选择。它也解释了为什么“窗口大小乘层数”不能直接当成模型真正的有效上下文：信息虽然可以逐层传播，但每一步都会引入压缩和误差。

### 4.3 DCA：重构长序列的相对位置关系

**Dual Chunk Attention（DCA）**不是简单把 RoPE base 改大，也不是普通的 sliding window。它把长序列切成多个不超过训练长度的 chunk，并重新设计 chunk 内和 chunk 间的相对位置矩阵：

- **Intra-chunk attention**：同一 chunk 内保留原始位置关系；
- **Inter-chunk attention**：不同 chunk 之间用压缩后的相对位置表示；
- **Successive-chunk attention**：对相邻 chunk 保留更细的局部关系，避免 chunk 边界断裂。

DCA 的重要性在于：它尽量保留原始 RoPE 在训练长度内的行为，同时让不同 chunk 之间能够通信；它可以与 YaRN 等 RoPE scaling 组合，并且兼容 FlashAttention。Qwen2 用 DCA + YaRN 将 32K 训练长度外推到约 128K。

![DCA 的 chunk 内、chunk 间和相邻 chunk 注意力](/assets/img/qwen/dca-attention.webp){: .qwen-figure width="760" }

<div class="qwen-caption">图 6 · DCA 的相对位置重构示意。来源：[Training-Free Long-Context Scaling with Dual Chunk Attention](https://arxiv.org/abs/2402.17463)，Figure 2，PDF p.4。</div>

与 PI/NTK/YaRN 的关系可以这样记：

```text
PI / NTK / YaRN：修改位置或频率如何编码
DCA：修改长序列中不同 chunk 如何组织相对位置
```

### 4.4 稀疏、扩张和全局连接

- **BigBird**：局部窗口 + 随机连接 + 全局 token，在近似线性复杂度下保持图上的全局连通性。[BigBird](https://arxiv.org/abs/2007.14062)
- **LongNet**：使用不同膨胀率的 dilated attention，让远距离 token 以更稀疏的方式连接，理论上可以把感受野扩展到极长序列。[LongNet](https://arxiv.org/abs/2307.02486)
- **Longformer**：为不同任务指定全局 token，例如文档分类中的 `[CLS]` 或问答中的问题 token。

这些方法改变了注意力图的结构。它们的核心取舍是：**用稀疏路径换取更低的计算量，但必须设计足够好的跨段连接，否则重要信息可能无法到达。**

## 5. 长上下文训练：让模型真的学会使用远距离信息

如果只做推理时的 RoPE 外推，模型只是“可以计算更大的位置”；要提升有效理解能力，通常还需要长上下文继续预训练或长上下文微调。

### 5.1 Progressive Long-Context Training：逐级增加长度

直接用 1M token 训练成本极高，因为全注意力的计算量和显存压力都会急剧增长。工程上更常见的是课程式扩展：

```text
4K → 32K → 64K → 128K → 256K
```

每一级只使用一部分当前长度样本，同时保留短样本，避免模型忘记短上下文能力。通常还会同步调整 RoPE base，并在最后阶段加入高质量长文档、书籍、代码仓库和合成长样本。

Qwen 的具体路线是：

- **Qwen-1**：训练长度约 2K，主要靠 NTK、LogN 和窗口注意力做推理时扩展；
- **Qwen1.5**：官方宣称全尺寸支持 32K，模型配置也包含 32K 的最大位置数和更大的 RoPE base，但公开报告没有完整披露长上下文训练配方；
- **Qwen2**：预训练末期从 4K 扩展到 32K，RoPE base 从 10,000 调到 1,000,000，再用 YARN + DCA 外推到最高约 131K；
- **Qwen2.5**：普通开源模型采用 4K→32K 两阶段训练，并通过 YARN + DCA 支持 128K；
- **Qwen2.5-1M**：继续把训练长度逐级扩展到 256K，再用 DCA + YaRN 推理外推到 1M；
- **Qwen3**：前两个预训练阶段使用 4K，最后的 Long Context Stage 使用 32K 长文本，并继续使用 ABF、YARN 和 DCA。

这里要严格区分：**训练到 256K、推理外推到 1M**，和“直接训练了 1M token”不是一回事。

### 5.2 PoSE：用位置跳跃模拟长位置

**PoSE（Positional Skip-wise Training）**的目标是：在显存只能容纳短序列时，让模型看到更大的位置编号。

它把一段短训练序列切成若干块，并给块之间加入随机的位置跳跃。模型一次仍然只处理短序列，但不同 batch 会覆盖目标长序列中的不同位置区间。

PoSE 解决的是位置覆盖问题，不能完全代替真正的长序列注意力；它适合在有限资源下做位置微调。[PoSE](https://arxiv.org/abs/2309.10400)

### 5.3 LongLoRA：训练时稀疏，推理时恢复全注意力

**LongLoRA**使用 shifted sparse attention（S²-Attn）降低长上下文微调成本：不同 attention head 使用错开的局部窗口，让跨块信息逐步流动；同时用 LoRA 微调，并额外训练 embedding 和 normalization 层。

它的一个工程特点是：稀疏注意力主要用于训练，推理时可以恢复完整注意力，因此不会把训练阶段的稀疏模式直接带到最终模型中。[LongLoRA](https://arxiv.org/abs/2309.12307)

### 5.4 长上下文 SFT/RL 也要单独设计

长上下文继续预训练只让模型获得长序列建模能力，SFT 还要教它在长输入中完成任务。Qwen2.5-Turbo 的后训练就是一个典型例子：先用不超过 32K 的短指令维持基本能力，再混入最高 262K 的长指令；RL 阶段仍主要使用短输入，因为长上下文 RL 的成本高、奖励模型也更难设计。

这说明长上下文训练不是把所有阶段都机械地改成同一个最大长度，而是需要在**能力、成本和奖励信号质量**之间做分阶段安排。

## 6. 记忆、缓存与流式输入

另一类方法不直接修改 RoPE，而是让模型不必把全部历史 token 都以完整 KV 的形式留在当前注意力中。

### 6.1 Transformer-XL：跨 segment 复用隐藏状态

Transformer-XL 把长文本切成 segment，并将前一个 segment 的隐藏状态作为下一个 segment 的记忆。它还使用相对位置编码，使记忆跨 segment 时不依赖绝对位置编号。

优点是可以突破单个 segment 的计算范围；缺点是记忆通常被截断或停止反向传播，信息并不是完整、无损地保留。[Transformer-XL](https://arxiv.org/abs/1901.02860)

### 6.2 StreamingLLM：保留 attention sinks 和最近窗口

在流式解码中，最直接的做法是只保留最近 $W$ 个 token 的 KV。但实验发现，模型会把大量注意力分配给最前面的少数 token，即使这些 token 没有明显语义价值。作者称之为 **attention sinks**。

StreamingLLM 因此保留两部分缓存：

```text
最前面的若干 sink tokens + 最近的 W 个 token
```

这样可以用固定大小的 KV cache 在很长的输入流上稳定运行，而不需要重新训练模型。

![StreamingLLM 与普通窗口缓存的比较](/assets/img/context/streamingllm.webp){: .qwen-figure width="760" }

<div class="qwen-caption">图 7 · Dense attention、window attention、重计算窗口和 StreamingLLM 的缓存策略。来源：[StreamingLLM 原论文，Figure 1，PDF p.2](https://arxiv.org/abs/2309.17453)。</div>

但 StreamingLLM 不是“无限上下文理解”：被丢弃的中间历史无法再被直接访问，更适合连续对话、日志流和实时输入。[StreamingLLM](https://arxiv.org/abs/2309.17453)

### 6.3 Infini-attention 与压缩记忆

Infini-attention 在一个 Transformer block 中同时保留局部因果注意力和压缩长期记忆。新 token 到来时，长期信息被更新到一个固定大小的记忆状态中，推理时不必保存全部历史 token。

这类方法的关键取舍是：内存从随序列长度增长变成有界状态，但被压缩的历史不再能以原 token 级别精确恢复；它更像一个可学习的摘要器，而不是完整 KV cache。[Infini-attention](https://arxiv.org/abs/2404.07143)

## 7. 系统与推理优化：能跑得更长，不等于模型懂得更多

### 7.1 FlashAttention：精确注意力的 IO 优化

FlashAttention 不改变 attention 的数学定义，而是使用 tiling 和片上 SRAM，避免显式保存完整的 $N\times N$ attention matrix。它主要减少 HBM 读写和中间显存，提升长序列 prefill 的可运行长度。

因此：

> FlashAttention 降低的是精确注意力的系统成本，不改变 RoPE 的训练范围，也不改变模型的语义上下文能力。

### 7.2 Ring Attention：把完整注意力分布到多张卡

Ring Attention 将序列分成 block，每张卡负责自己的 query block，同时在设备环中轮换 KV block。通信与计算重叠后，多张卡可以共同承载更长的序列。

它保持完整 attention 的数学结果，解决的是单卡显存和分布式训练/推理问题；如果模型没有长位置训练或外推机制，Ring Attention 也不会自动提供长上下文理解。

![Ring Attention 的设备环与最大上下文长度](/assets/img/context/ringattention.webp){: .qwen-figure width="760" }

<div class="qwen-caption">图 8 · Ring Attention 通过 blockwise attention 和设备间 KV 轮换扩大可承载的上下文。来源：[Ring Attention 原论文，Figure 1，PDF p.2](https://arxiv.org/abs/2310.01889)。</div>

### 7.3 MInference、稀疏 prefill 与 chunked prefill

长上下文推理的瓶颈往往首先出现在 prefill。MInference 根据不同 attention head 的模式，使用 A-shape、Vertical-Slash、Block-Sparse 等稀疏 pattern，减少预填充阶段的计算；chunked prefill 则把超长输入拆成可调度的块。

这些方法可以显著提高速度，但需要强调：它们是**推理加速**，不是位置外推。Qwen2.5-1M 的报告同时使用了 DCA/YaRN（语义长度）和稀疏 prefill/调度优化（系统效率），两者解决的是不同层次的问题。[MInference](https://arxiv.org/abs/2407.02490)

## 8. Qwen 的长上下文路线

| 系列 | 长上下文训练 | 推理/外推 | 主要方法 | 需要注意的边界 |
| --- | --- | --- | --- | --- |
| Qwen-1 | 约 2K | 8K 以上 | NTK-aware、Dynamic NTK、LogN、分层窗口 | 主要是推理时扩展，不等于长上下文训练 |
| Qwen1.5 | 公开细节有限；官方统一宣称 32K | 32K 配置 | 更大的 RoPE base、32K 配置；具体 recipe 未完整披露 | 不宜直接断言使用了 Qwen-1 的 dynamic NTK |
| Qwen2 | 末期 4K→32K | 最高约 128K | RoPE base 10K→1M、YARN、DCA | 32K 是训练长度，128K 主要是外推能力 |
| Qwen2.5 | 普通开源模型 4K→32K | 最高约 128K | ABF、YARN、DCA；Turbo 渐进长训 | Turbo 与普通开源 Dense 不能混写 |
| Qwen2.5-1M | 4K→32K→65K→131K→262K | 1M | 长上下文 SFT、DCA、YaRN、稀疏 prefill | 1M 是外推/系统优化后的可用目标，不是直接 1M 训练 |
| Qwen3 | 4K 通用/推理阶段，最后 32K 长上下文 | 最高约 128K | ABF、YARN、DCA | 仍要区分 32K 训练与推理外推 |

这一条路线可以概括成：

```text
Qwen-1：推理时外推
   ↓
Qwen1.5：32K 配置与工程化支持
   ↓
Qwen2：32K 长上下文训练 + DCA/YaRN 外推
   ↓
Qwen2.5：更高质量长数据、结构化长任务、1M 工程分支
   ↓
Qwen3：长上下文训练继续保留，同时服务于推理、工具和 Agent
```

## 9. 方法横向比较

| 方法 | 改动位置 | 是否需要长上下文训练 | 主要降低什么 | 主要风险 | 代表模型/系统 |
| --- | --- | --- | --- | --- | --- |
| PI | 缩放 RoPE 位置索引 | 通常需要少量微调 | 位置分布外问题 | 所有位置被压缩 | Long-context LLaMA |
| NTK-aware | 修改 RoPE base | 可训练无关或少量微调 | 位置外推 | 规则依赖经验，倍率过大易退化 | Code Llama、Qwen 相关实践 |
| Dynamic NTK | 当前长度动态修改 RoPE scale | 通常不需要完整长训 | 位置外推 | KV cache 与变化频率的兼容 | Qwen-1、社区实现 |
| LogN | 缩放 QK attention logits | 不需要 | 注意力熵/数值稳定 | 不是位置扩展的完整方案 | Qwen-1 |
| YaRN | NTK-by-parts + attention scaling | 少量微调或推理组合 | 位置和注意力分布 | 超大倍率仍需长训 | LLaMA、Qwen2/2.5 相关路线 |
| LongRoPE | 每个 RoPE 维度非均匀搜索 | 渐进微调 | 极大位置范围 | 搜索与回调训练成本 | LLaMA 2M 扩展 |
| Window/SWA | 局部注意力 | 需要按任务训练/适配 | $O(N^2)$ 计算、KV cache | 远距离直连被截断 | Longformer、Mistral |
| DCA | 重构 chunk 间相对位置 | 可训练无关 | 长序列相对位置和注意力 | chunk 设计与边界处理 | Qwen2、Qwen2.5 |
| StreamingLLM | sink + 最近窗口 KV | 不需要 | 流式 KV cache | 被淘汰历史不可恢复 | StreamingLLM |
| Infini-attention | 压缩长期记忆 | 需要训练记忆机制 | 有界内存 | 压缩损失细节 | Infini-attention |
| Flash/Ring Attention | 内核/分布式系统 | 不改变模型语义 | 显存、带宽和并行 | 需要硬件/通信支持 | FlashAttention、Ring Attention |
| MInference | 稀疏 prefill | 不改变模型权重 | 超长输入的 prefill 速度 | 稀疏 pattern 可能漏信息 | Qwen2、Llama 系列推理 |

## 10. 怎么判断一个方法真的有效？

### 10.1 不要只看“最大长度”

至少要同时报告：

- 预训练长度和长上下文微调长度；
- 推理时使用的 RoPE scaling、DCA 或稀疏 attention 配置；
- prefill 延迟、decode 吞吐和 KV cache 显存；
- 位置外推时短上下文能力是否回退。

### 10.2 困惑度只是第一关

长文本 PPL 可以看模型是否整体退化，但不能证明模型找得到关键信息。常见测试包括：

- **Passkey / Needle-in-a-Haystack**：测试能否检索埋藏信息；
- **RULER**：组合检索、聚合、长距离依赖和多步任务；
- **LongBench**：长文档问答、摘要、代码和多语言任务；
- **Long-context QA / multi-hop**：测试跨多个位置组合证据的能力。

如果只在开头或结尾插入一个 passkey，可能高估模型的真实长文档能力；还需要测试中间位置、多个干扰项和跨段推理。

### 10.3 工程上最容易踩的坑

1. **只改 `max_position_embeddings`**：这只改变允许的索引范围，不会自动修复 RoPE 外推；
2. **训练和推理的 RoPE 参数不一致**：`rope_theta`、scaling factor、原始上下文长度必须对应；
3. **把训练长度和外推长度混写**：32K 训练、128K 推理和 1M 配置不是同一个承诺；
4. **忽略 KV cache**：prefill 能跑通，不代表 decode 能在显存中维持全部历史；
5. **把 FlashAttention/Ring Attention 当成语义扩展**：它们主要改善系统可运行性；
6. **只测 PPL 或单一 NIAH**：长上下文有效性必须用多种任务评估；
7. **过度依赖 sliding window**：窗口降低成本，但可能阻断需要直接访问的远距离证据。

## 11. 结语：上下文扩展不是一项技术，而是一层系统

从技术演进看，长上下文不是“把 RoPE 公式改一下”就结束了，而是多个层次的组合：

```text
位置层：PI / NTK-aware / Dynamic NTK / YaRN / LongRoPE
注意力层：Window / Sparse / DCA / Dilated Attention
训练层：长上下文继续预训练 / PoSE / LongLoRA / 长上下文 SFT
记忆层：Transformer-XL / StreamingLLM / Infini-attention
系统层：FlashAttention / Ring Attention / MInference / Chunked Prefill
```

最重要的区分是：

> **位置外推让模型“能表示更远的位置”；长上下文训练让模型“学会使用远处信息”；稀疏注意力和系统优化让这件事“在有限硬件上跑得动”；记忆机制则让模型“不必永远保存全部历史”。**

Qwen 的路线正好把这几层串起来：Qwen-1 先用 NTK、LogN 和分层窗口做训练无关的推理扩展；Qwen2 开始把长上下文继续预训练、ABF、DCA 和 YaRN 组合起来；Qwen2.5-1M 再把渐进式长训、长上下文 SFT、DCA/YaRN 和稀疏 prefill 组合成完整系统。
