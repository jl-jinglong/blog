把上下文窗口从 4K 调到 128K，很多人以为改个配置数字就够了。但配置只是"允许"模型接收长输入，真正要解决的是三件彼此独立的事：

1. **位置没见过**：模型只学过 4K 以内的位置，第 100000 个 token 它从没遇到过；
2. **算力吃不消**：注意力计算量随长度平方增长，KV cache 随长度线性增长；
3. **没学过用远处信息**：就算位置能算、显存够用，模型也可能只顾着看最近几百个 token。

第 3 条常被忽略，但它才是"能接收"和"真理解"的分界线。这篇笔记讲**位置、注意力、训练**这三条方法线；**KV cache、流式推理、分布式注意力**这些偏系统实现的内容（"跑不跑得动"）不在这里展开。RoPE 本身的原理见[大模型中的位置编码](/posts/positional-encoding/)。

## 1. 先把几个"长度"分开

设训练时的最大长度为 $L$，推理时想达到 $L'$，扩展倍率是：

$$
s = \frac{L'}{L}.
$$

- $L$：训练时真正见过的最大长度。
- $L'$：推理时想用的目标长度。
- $s$：扩展了几倍。$L=4\text{K}$、$L'=128\text{K}$ 时 $s=32$。

但"长度"在实际讨论里至少指四件事，混着说就会得出错误结论：

| 名称 | 含义 | 例子 |
| --- | --- | --- |
| 训练长度 | 预训练或微调时真正出现过的最大长度 | Qwen-1 约 2K；Qwen2 末期 32K |
| 配置长度 | 配置和推理框架允许的最大位置数 | `max_position_embeddings=32768` |
| 外推长度 | 靠位置缩放或注意力重构，没重新长训时尝试的长度 | Qwen2 由 32K 外推到约 128K |
| 有效理解长度 | 在检索、总结、问答上仍然可靠的长度 | 要靠 NIAH、RULER、LongBench 等评测 |

> **"支持 128K"通常指配置长度或外推长度，不等于"能有效理解 128K"。**
>
> 模型完全可以接收 128K 个 token，却只对开头结尾敏感；也可以靠 RoPE 外推让位置索引不报错，却没有稳定的长距离检索能力。

## 2. 上下文变长，模型卡在哪

### 2.1 位置：训练时没见过这么远的位置

RoPE 把 query 和 key 的每一对维度看成一个二维平面，位置 $m$ 的第 $i$ 个频率旋转角度是：

$$
\phi_{m,i}=m\,\omega_i,
\qquad
\omega_i=b^{-2i/d}.
$$

- $m$：token 的绝对位置。
- $\omega_i$：第 $i$ 组维度的旋转频率。
- $b$：base，通常取 10000，决定各频率的整体尺度。
- $d$：注意力头的维度。

可以把它想成**一组转速不同的钟表指针**：低频维度转得慢，负责区分大跨度位置；高频维度转得快，负责区分相邻位置。

问题在于**模型只见过 $0\le m<L$ 这段角度**。推理时把 $m$ 推到 128K，高频指针已经多转了几十圈，落在一组训练中从未出现的角度组合上。模型对这些组合没有正确响应，注意力分数就会不稳定。

### 2.2 训练：模型不会自动学会用远处信息

位置问题解决了，不代表模型会用远处的信息。如果训练数据里从没出现过 100K 长的样本，模型可能只关注最近的局部上下文，或者出现明显的 `lost in the middle`——开头结尾记得住，中间记不住；也可能能检索孤立的 passkey，却不会做需要多处信息联合的推理。

所以长上下文能力必须靠**训练**建立，位置外推只是让它"有可能"用上。

## 3. 位置扩展：让模型"见过"更远的位置

这类方法不动 Transformer 主干，只改 RoPE 的位置索引、频率或注意力分数。共同思路是：**既然模型没见过 $L$ 以外的位置，就把这些位置映射回它见过的范围，或者让远处位置的表示变化得更平缓。**

### 3.1 Position Interpolation：等比例压回旧范围

**Position Interpolation（PI）**最直接：不让模型看到 $0$ 到 $L'-1$ 的新位置，而是把位置整体缩小 $s$ 倍：

$$
m' = \frac{m}{s}.
$$

- $m$：推理时的真实位置。
- $m'$：实际喂给 RoPE 的位置。
- $s=L'/L$：扩展倍率。

$L=4\text{K}$、$L'=32\text{K}$ 时 $s=8$：真实位置 32000 会被当成 4000 来编码，正好落在训练范围的上边界附近。

**代价**：所有位置被等比例压缩，相邻 token 之间的角度差也缩小了 8 倍，近距离分辨率随之下降——原本能区分"相邻"和"隔一个"的指针，现在转得太慢，区分不出来。所以 PI 通常需要少量长上下文微调恢复性能。原论文在 LLaMA 上用很少的微调步数把 2K 扩到了 32K。

> PI 解决的是"位置落到训练分布外"，**不解决**注意力的 $O(N^2)$ 成本。

### 3.2 NTK-aware scaling：高频别动，低频多拉

PI 的毛病是**一刀切**：所有维度都除以同一个 $s$。但 RoPE 的不同维度负责不同尺度——高频管局部，低频管长距离。把高频也一起压缩，等于白白牺牲局部分辨率。

**NTK-aware scaling** 不改位置，改 base：

$$
b' = b\,s^{d/(d-2)}.
$$

- $b$：原来的 base，通常 10000。
- $b'$：缩放后的 base。
- $d$：注意力头维度。
- $s$：扩展倍率。

base 变大后 $\omega_i=b^{-2i/d}$ 整体变小，但**各维度变小的幅度不一样**：低频维度频率降得更多（变化更慢、覆盖更长距离），高频维度相对保留原来的转速（局部区分度还在）。这正是"高频别动、低频多拉"。

NTK-aware 最初靠社区实现和工程文章传播，YaRN 论文对它做了系统整理。所以最好把它称为一种**方法**，不要包装成一篇独立统一的正式论文。

**ABF（Adjusted Base Frequency）**是同一公式在训练侧的用法：长上下文继续预训练时直接把 base 调大，例如 10,000 → 1,000,000。区别是 NTK-aware 常作为训练无关的推理技巧，ABF 属于**继续预训练配方的一部分**，需要长文本数据让模型重新适应位置分布。

### 3.3 Dynamic NTK：缩放倍率跟着当前长度走

固定 NTK-aware 有个前提：得**提前知道**目标长度。但推理时序列是一点点变长的，用一个为 128K 准备的 $s$ 去处理只有 8K 的请求，等于无谓地改动了本来没问题的位置。

**Dynamic NTK** 让 $s$ 随当前长度变化：

$$
s(n)=\max\left(1,\frac{n}{L}\right).
$$

- $n$：当前实际的序列长度。
- $L$：训练长度。

$n\le L$ 时 $s=1$，完全保持原 RoPE；只有超过训练长度后才开始缩放，并随长度逐步加大。短请求不受影响，长请求才进入扩展模式。

> **一个容易忽略的坑**：长度一变就改 RoPE 频率，之前缓存的旋转后 K 就对不上新频率了。实现要么缓存**旋转前**的 K，要么同步更新缓存。所以它不是"在 RoPE 里加个 if"那么简单。

### 3.4 LogN-Scaling：改注意力的"温度"

LogN-Scaling 常和 NTK-aware 一起出现，但它**不是位置编码方法**，调整的是 attention logits 的尺度：

$$
Q' = Q\cdot \frac{\log n}{\log L},
\qquad
\frac{Q'K^\top}{\sqrt{d_h}}
=\frac{\log n}{\log L}\cdot\frac{QK^\top}{\sqrt{d_h}}.
$$

- $L$：训练长度。
- $n$：当前上下文长度。
- $\frac{\log n}{\log L}$：缩放因子，序列越长越大。

**为什么需要它？** softmax 对输入尺度很敏感。序列变长后 logits 分布会变化，注意力要么越来越尖锐（只盯住极少数 token），要么越来越平坦（被稀释）。乘上这个因子相当于给 softmax 调"温度"。

Qwen-1 的实现是在 query 上乘这个因子，等价于缩放 QK logits——**不是**给 value 乘系数。它解决数值稳定性，不能单独解决 RoPE 的未见位置，也不能降低 $O(N^2)$ 的计算量。

### 3.5 YaRN：按波长分档 + 温度补偿

**YaRN（Yet another RoPE extensioN）**是对 PI 和 NTK-aware 的组合改进，含两部分：

1. **NTK-by-parts interpolation**：不再"高频全留、低频全插"，而是按每个维度对应的**波长**决定插值程度。波长比训练长度还短的维度（高频，管局部）基本不动；波长很长的维度（低频，管远距离）做完整插值；中间频率平滑过渡。
2. **Attention scaling**：插值后注意力熵会变化，再对 logits 加长度相关的温度修正：

$$
\sqrt{\frac{1}{t}}=1+0.1\ln s.
$$

- $t$：与 attention temperature 相关的量。
- $s$：扩展倍率。$\ln s$ 越大，补偿越强。

![YaRN 与其他插值方法的关系](/assets/img/context/yarn-summary.webp){: .qwen-figure width="760" }

图 3 · YaRN 论文对 RoPE、PI、NTK-aware、NTK-by-parts 和 attention scaling 关系的概览。来源：[YaRN 原论文，Figure 1，PDF 第 2 页](https://arxiv.org/abs/2309.00071)。
{: .qwen-caption }

YaRN 的价值在于**同时处理位置频率和注意力分布**，因此用很少的长上下文微调步数就能拿到较大扩展，也可以和 Dynamic NTK 组合做推理时扩展。

### 3.6 LongRoPE 与其他位置方案

前面几种用的都是**人为设计**的缩放规则。**LongRoPE** 更进一步：直接搜索每个 RoPE 维度该缩多少，允许非均匀缩放，同时保留一部分初始 token 的原始位置（避免开头的位置信息被破坏）。

![LongRoPE 的非均匀位置插值](/assets/img/context/longrope.webp){: .qwen-figure width="760" }

图 4 · 直接外推、线性位置插值与 LongRoPE 非均匀插值的对比。来源：[LongRoPE 原论文，Figure 2，PDF 第 3 页](https://arxiv.org/abs/2402.13753)。
{: .qwen-caption }

它的训练是渐进式的：先扩到 256K，再扩到约 2M；同时用短上下文回调微调把原来的 4K/8K 能力找回来。这体现了一个趋势：**扩展倍率越大，越需要非均匀的频率设计和渐进式训练。**

另外两条常被提到的路线：

- **ALiBi**：不用显式位置向量，直接在 attention logits 上减去和距离成正比的惩罚 $-m\cdot|i-j|$，不同 head 用不同斜率 $m$。简单、没有位置表，但距离关系只有"越远越弱"这一种。
- **XPos**：在 RoPE 基础上对 Q/K 做互补的长度缩放，试图在远距离上保住分辨率。

## 4. 注意力模式：不让每个 token 看完整的 $N\times N$

位置扩展解决"位置怎么表示"，注意力模式解决"**哪些 token 要交互**"。这类方法主要降低计算成本，代价是牺牲一部分全局可见性。### 4.1 Sliding Window Attention：只看邻居

**Sliding Window Attention（SWA）**让位置 $i$ 只关注附近宽度为 $w$ 的 token：

$$
j\in[i-w+1,\ i].
$$

- $i$：当前 token 的位置。
- $w$：窗口宽度。
- $j$：能参与注意力的 key 的位置。

复杂度从 $O(N^2)$ 降到近似 $O(Nw)$。

**远处信息怎么办？** 靠**多层堆叠**逐层传播：第 1 层里 token $i$ 只能看到前 $w$ 个，但第 2 层里它看到的这些 token 各自又看过它们的前 $w$ 个，感受野翻倍。$k$ 层之后有效感受野约为 $k\cdot w$。

> 这个"感受野"是**理论上界**，不是真正的全局注意力。信息每传一层都会被压缩一次，传得越远损失越大。所以"窗口大小 × 层数"不能直接当成有效上下文长度。

![Longformer 的几种注意力模式](/assets/img/context/longformer-patterns.webp){: .qwen-figure width="760" }

图 5 · Full、sliding、dilated 和 global+sliding 四种注意力模式。来源：[Longformer 原论文，Figure 2，PDF 第 3 页](https://arxiv.org/abs/2004.05150)。
{: .qwen-caption }

Longformer 把滑动窗口、扩张窗口和全局 token 组合起来；Mistral 7B 用窗口 4096 的 SWA 加滚动 KV cache。

### 4.2 DCA：分块处理，块内保留、块间压缩

**Dual Chunk Attention（DCA）**针对 RoPE 在长序列上的一个具体麻烦：序列一旦超过训练长度，块与块之间的相对距离就落到了模型没见过的范围。

它把长序列切成多个**不超过训练长度**的 chunk，对不同位置关系用不同规则：

- **Intra-chunk（块内）**：同 chunk 内保持**原始**位置关系，因为块长没超过训练长度，模型完全熟悉；
- **Inter-chunk（块间）**：不同 chunk 之间改用**压缩后**的相对位置，把距离限制在模型见过的范围内；
- **Successive-chunk（相邻块）**：相邻 chunk 边界附近保留更细的局部关系，避免信息在边界断开。

![DCA 的 chunk 内、chunk 间和相邻 chunk 注意力](/assets/img/qwen/dca-attention.webp){: .qwen-figure width="760" }

图 6 · DCA 的相对位置重构示意。来源：[Training-Free Long-Context Scaling with Dual Chunk Attention](https://arxiv.org/abs/2402.17463)，Figure 2，PDF 第 4 页。
{: .qwen-caption }

分工可以这样记：

```text
PI / NTK / YaRN：修改"位置或频率怎么编码"
DCA：          修改"长序列里不同 chunk 之间怎么组织相对位置"
```

DCA 可以训练无关地使用，能和 YaRN 组合，也兼容 FlashAttention。Qwen2 就是靠 DCA + YaRN 把 32K 训练长度外推到约 128K。

### 4.3 分层窗口与稀疏连接

**分层窗口**：Qwen-1 没有公开每层的窗口数字，但给了一个重要观察——低层更依赖局部信息，可以用短窗口；高层需要整合更远语义，可以用长窗口。

**稀疏、扩张与全局连接**：**BigBird** 用局部窗口 + 随机连接 + 全局 token，在近似线性复杂度下保持全局连通性；**LongNet** 用不同膨胀率的 dilated attention，让远距离 token 以更稀疏的方式连接；**Longformer** 为不同任务指定全局 token，比如文档分类的 `[CLS]`。

它们的共同取舍是：**用稀疏路径换低计算量，但必须设计足够好的跨段连接，否则重要信息传不到。**

## 5. 长上下文训练：让模型真的学会用远处信息

只做推理时的 RoPE 外推，模型只是"**能计算**更大的位置"；要让它真的会用，还得靠训练。

### 5.1 逐级加长：课程式扩展

直接用 1M token 训练成本极高。工程上更常见的是**课程式**逐级扩展：

```text
4K → 32K → 64K → 128K → 256K
```

每一级只用一部分该长度的样本，同时**保留短样本**，避免模型忘掉短上下文能力。通常还会同步调整 RoPE base，并在最后阶段加入高质量长文档、书籍、代码仓库和合成长样本。

Qwen 系列的实际路线：Qwen-1 训练长度约 2K，靠 NTK、LogN 和分层窗口做推理时扩展；Qwen2 在预训练末期从 4K 扩到 32K，把 RoPE base 从 10,000 提到 1,000,000，再用 YaRN + DCA 外推到约 128K；Qwen2.5 沿用 4K→32K 加 ABF/YaRN/DCA，Turbo 版本渐进扩到 256K；Qwen2.5-1M 逐级扩到 262K 后外推到 1M；Qwen3 在最后一个阶段用 32K 长文本训练。

要严格区分：**训练到 256K、推理外推到 1M**，和"直接训练了 1M token"完全不是一回事。

### 5.2 省显存的长训技巧：PoSE 与 LongLoRA

这两个方法解决同一个矛盾：想训练长序列，但显存只放得下短序列。

**PoSE（Positional Skip-wise Training）** 的思路是：显存不够就**不真的塞长序列**，只让模型看到**大的位置编号**。它把一段短训练序列切成若干块，在块之间插入随机的位置跳跃，于是一次前向仍只处理短序列，但不同 batch 会覆盖目标长序列中的不同位置区间。它解决的是**位置覆盖**，不能替代真正的长序列注意力。

**LongLoRA** 用 shifted sparse attention（S²-Attn）：不同 attention head 使用**错开**的局部窗口，让跨块信息通过多层逐步流动；再配合 LoRA 微调。它有个实用的工程特点：**稀疏注意力只用于训练，推理时恢复完整注意力**。

### 5.3 后训练也要单独设计

长上下文继续预训练只让模型获得长序列**建模**能力，SFT 还要教它在长输入里**完成任务**。Qwen2.5-Turbo 是个典型例子：先用不超过 32K 的短指令维持基本能力，再混入最高 262K 的长指令；而 RL 阶段仍主要用短输入，因为长上下文 RL 成本高、奖励模型也更难设计。

所以长上下文训练不是把所有阶段机械地改成同一个最大长度，而是要在**能力、成本和奖励信号质量**之间做分阶段安排。

## 6. 方法横向比较

| 方法 | 改哪里 | 要长训吗 | 主要解决 | 主要风险 |
| --- | --- | --- | --- | --- |
| PI | 等比例缩放位置索引 | 通常需少量微调 | 位置落在训练范围外 | 近距分辨率下降 |
| NTK-aware | 改 RoPE base | 可训练无关 | 位置外推 | 规则靠经验，倍率过大退化 |
| Dynamic NTK | 按当前长度动态改 scale | 通常不需完整长训 | 位置外推 | 与 KV cache 的频率一致性 |
| LogN | 缩放 QK logits | 不需要 | 注意力熵的数值稳定 | 不是完整的位置扩展方案 |
| YaRN | 按波长分档插值 + 温度补偿 | 少量微调或推理组合 | 位置和注意力分布 | 超大倍率仍需长训 |
| LongRoPE | 逐维度搜索非均匀缩放 | 渐进微调 | 极大位置范围 | 搜索与回调训练成本高 |
| Window/SWA | 局部注意力 | 需按任务适配 | $O(N^2)$ 计算 | 远距离直连被截断 |
| DCA | 重构 chunk 间相对位置 | 可训练无关 | 长序列的相对位置 | chunk 设计与边界处理 |
| PoSE | 位置跳跃 | 需位置微调 | 显存不足下的位置覆盖 | 不能替代真正的长序列注意力 |
| LongLoRA | 训练时稀疏注意力 | 需要 | 长上下文微调成本 | 训练/推理模式不一致 |
